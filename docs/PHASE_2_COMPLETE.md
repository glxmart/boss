## How It Works

### Two-Layer Configuration System

**1. Project Defaults** (`.container-use/environment.json`)

- Generated by `boss bootstrap` command
- Uses `boss/worker-base:1.0.0` image
- Empty `setup_commands` (all in Docker image)
- Minimal `install_commands` (only project deps)
- Optimized environment variables

**2. Worker-Specific Overrides** (`conductor-mcp/worker-configs/*/container-config.json`)

- Security-engineer: Additional network hosts
- DevOps-engineer: Docker/K8s tools
- All others: Inherit 100% from base

### Configuration Merge Flow

```
Project spawns worker
       ↓
Container-use loads .container-use/environment.json (project defaults)
       ↓
Conductor loads worker-configs/_base/container-config.json (base)
       ↓
Conductor loads worker-configs/{type}/container-config.json (override)
       ↓
Deep merge: base + worker override
       ↓
Final config applied to container
```

We use `boss/worker-base:1.0.0` instead of `latest`.

## Technical Notes

### Configuration File Format

Container-use expects JSON format for `.container-use/environment.json`:

```typescript
interface ContainerUseConfig {
  base_image: string;
  setup_commands: string[];
  install_commands: string[];
  environment_variables: Record<string, string>;
  secrets: string[];
  network: {
    allowed_hosts: string[];
  };
}
```

### Path Resolution

```bash
# Project structure
my-boss-project/
├── .container-use/
│   └── environment.json    # ← Generated by boss-cli
├── .boss/
│   └── workers/
│       └── {type}/
│           └── ...
└── ...
```

### Environment Variable Expansion

Container-use supports variable expansion:

- `$PWD` - Current working directory
- `$PATH` - Appended to system PATH
- `${workerName}` - (BOSS-specific, replaced by conductor)
